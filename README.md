# 问道长生

一款修仙题材的**卡牌构筑肉鸽**（类似《杀戮尖塔》）。自练气至化神，历经五大境界，击败每个境界的劫主完成突破，最终渡过**九九天劫**飞升。

纯前端、零依赖、无需构建：用浏览器打开 `index.html` 即可游玩（也可直接分享单文件 `dist/xianxia.html`）。支持桌面与手机屏幕，进度自动存档。

## 快速开始

```bash
# 直接双击 index.html，或：
npx http-server .        # 任意静态服务器均可
node tools/build.js      # 生成单文件版 dist/xianxia.html
```

## 玩法

- **地图**：每个境界一张分支地图（自下而上），节点包括妖兽、妖王（精英）、奇遇、坊市、洞府（打坐回血 / 淬炼功法）与机缘宝箱，最上方是劫主。
- **战斗**：每回合获得灵力，打出功法牌；敌人头顶显示行动意图；护体在下回合开始时清空。
- **五行**：木→火→土→金→水→木相生。若上一张打出的牌五行**生**本牌，触发**相生**：伤害与护体 +50%，部分功法有额外效果。牌的五行**克制**敌人属性时伤害 +30%（木克土、土克水、水克火、火克金、金克木）。
- **成长**：战斗后三选一功法、法宝、丹药；洞府淬炼；坊市购买与「焚经断念」精简牌库；突破境界时获得额外机缘。
- **传承（局外成长）**：每次陨落或飞升都会留下**道果**，可永久强化开局、解锁道途；飞升后解锁更高**劫数**（敌人更强，道果更多）。

| 道途 | 气血 | 风格 | 初始法宝 |
| --- | --- | --- | --- |
| 剑修 | 84 | 多段连击、剑意叠加、剑阵 | 青锋古剑 |
| 体修 | 86 | 护体为矛、反震、以血换力 | 玄铁腕环 |
| 法修（需解锁） | 74 | 五行相生连锁、灼烧、过牌 | 五行珠 |
| 丹修（需解锁） | 74 | 中毒、丹药、回春 | 百草鼎 |

**操作**：点击卡牌出牌（需要目标时再点敌人）；`1`–`9` 选牌，`E` 结束回合，`Esc` 取消；触屏设备点一次选牌、再点一次打出。悬停（触屏为轻触）图标可查看状态、意图与法宝说明。

## 内容规模

79 张卡牌（四条道途 + 通用池，均可淬炼）· 5 个境界 · 38 种敌人（含 10 位妖王、5 位劫主）· 28 件法宝 · 10 种丹药 · 11 个奇遇 · 8 项传承 · 6 档劫数

## 项目结构

```
index.html            页面入口（开发时直接加载 src/ 与 css/）
src/data.js           静态数据：五行、状态、卡牌、职业、法宝、丹药、敌人、奇遇、传承
src/engine.js         游戏引擎（与 UI 解耦，可在 Node 中无头运行）：战斗、地图、奖励、商店、存档
src/ui.js             界面：渲染、交互、动效、合成音效
css/style.css         国风水墨主题，含窄屏适配
tools/build.js        内联为单文件 dist/xianxia.html
tests/audit.js        内容审计：数据 schema 校验，并逐一执行每张牌 / 每个敌人招式 / 每件法宝 / 每瓶丹药 / 每个奇遇选项
tests/sim.js          无头模拟：机器人打完整局，检查崩溃、存档往返一致性并粗测平衡
tests/e2e.js          浏览器端到端（Playwright）：点击 DOM 走完整局并截图
tests/shots.js        把状态摆到特定界面截图（商店、Boss、相生高亮、弹窗……）
tests/resume.js       浏览器存档 / 继续流程验证
```

## 开发与测试

```bash
npm test                          # 审计 + 每职业 60 局模拟（无需任何依赖）
node tests/sim.js 300 0           # 每职业 300 局，劫数 0；第三个参数为种子偏移
KILLERS=1 node tests/sim.js 200 2 # 同时统计各职业的主要死因
# 需要全局安装 playwright 的浏览器测试：
NODE_PATH=$(npm root -g) node tests/e2e.js ./shots 1280x800 mage
NODE_PATH=$(npm root -g) node tests/resume.js
```

### 设计说明

- 所有随机（地图、奖励、战斗洗牌）来自同一个可存档的种子随机数，状态保存在 `localStorage`。存档只在地图上写入，因此战斗中途刷新会回到进入该节点之前（且随机结果一致）。
- 引擎的流程由 `run.phase`（`map / battle / reward / shop / rest / event / chest / pick / cards / breakthrough / over`）与一个步骤队列驱动，UI 只是该状态的函数，机器人与浏览器共用同一套接口。
- 参考平衡（启发式机器人，劫数 0，每职业 200 局）：通关率约 36%–50%，死亡集中在各境界劫主；人类玩家通常会更高，劫数 1–5 用于提高难度。
